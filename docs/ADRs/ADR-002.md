### ADR-002: Escolha do Backend (PHP com Laravel e API REST) — Aprovado

**Contexto:** É necessária uma API com autenticação, regras de negócio claras (RN01 a RN18), validação de dados, jobs agendados (expiração, correspondências) e padrões consistentes para facilitar a evolução do código.


**Decisão:** Utilizar PHP 8.3 com Laravel 11, expondo uma API REST documentada em OpenAPI/Swagger, com Eloquent como ORM para MySQL, Form Requests para validação, Laravel Sanctum ou JWT para autenticação, filas em banco de dados e o agendador nativo (Task Scheduling) para os jobs recorrentes.

**Consequências:**

- (+) PHP é uma das linguagens mais usadas na web, com muita documentação, cursos e mão de obra disponível, inclusive em universidades.
- (+) Laravel traz pronto o que o MVP precisa: autenticação, validação, envio de e-mail, filas, agendador, autorização por papéis (policies) e migrações.
- (+) Eloquent usa consultas parametrizadas, reduzindo o risco de SQL Injection (RNF07), e tem integração nativa e madura com MySQL.
- (+) O agendador e as filas do Laravel cobrem expiração de anúncios (RN11), notificações e sugestão de correspondências sem infraestrutura extra (RNF19).
- (+) Hospedagem de PHP é abundante e barata, de planos compartilhados a contêineres.
- (−) A estrutura do Laravel é opinativa e tem curva de aprendizado para quem não conhece o framework.
- (−) PHP e JavaScript no frontend significam duas linguagens no projeto, em contrapartida à separação clara entre API e interface.
- (−) Em carga muito alta o PHP tradicional consome mais recursos que runtimes assíncronos, o que é irrelevante para o volume do MVP (RNF18).
