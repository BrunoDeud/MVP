# ADR-003 — Banco de dados SQLite em arquivo local

- **Status:** Aceita para a versão local simplificada do MVP
- **Data:** 2026-10-22
- **Substitui:** a decisão anterior de utilizar MySQL 8.0 com InnoDB e índices FULLTEXT.

## Contexto

O sistema precisa persistir usuários, anúncios, reivindicações, denúncias, mensagens e ações de moderação. Na versão original, esses dados seriam armazenados em um serviço MySQL separado. Para facilitar a execução da demonstração, queremos evitar instalar, iniciar e configurar um servidor de banco de dados.

## Decisão

Utilizar **SQLite**, acessado pelo módulo `sqlite3` da biblioteca padrão do Python. O arquivo de banco é criado automaticamente em `data/encontrei.sqlite3` no primeiro início da aplicação. O esquema é inicializado pelo código de `init_db()` em `app.py`, que também cria contas e anúncios de demonstração quando necessário.

O esquema atual contém as tabelas `users`, `items`, `claims`, `reports`, `moderation_actions` e `messages`. As relações são implementadas com chaves estrangeiras; a aplicação habilita `PRAGMA foreign_keys = ON` em cada conexão. Restrições e índices únicos ajudam a prevenir e-mails duplicados, denúncias repetidas e reivindicações ativas duplicadas do mesmo usuário para o mesmo item.

## Alternativas consideradas

- **MySQL:** adequado para uma aplicação compartilhada e implantação em servidor, mas exige um serviço independente e configuração de credenciais.
- **JSON ou arquivos de texto:** dispensariam SQL, mas dificultariam consultas relacionais, transações e validações de integridade.
- **SQLite:** escolhido porque é relacional, transacional e já vem com Python, mantendo o banco dentro da pasta do projeto.

## Consequências

### Positivas

- Não é preciso instalar nem iniciar um servidor MySQL.
- Os dados persistem entre execuções no arquivo `data/encontrei.sqlite3`.
- O banco e os dados de demonstração são criados automaticamente.
- A aplicação usa consultas parametrizadas e transações para as operações de dados.
- É simples reiniciar a demonstração: basta encerrar a aplicação e remover o banco local, se for desejado recriar os dados iniciais.

### Negativas e limites conhecidos

- O arquivo fica armazenado no próprio computador e precisa ser copiado junto com os demais dados se for necessário preservar o estado da demonstração.
- SQLite não substitui um banco gerenciado para múltiplas instâncias de aplicação ou carga concorrente elevada.
- O arquivo contém dados de autenticação e dados da aplicação; deve ser tratado como dado local e não ser publicado no repositório.
- A resposta de verificação é mantida no banco local. Embora não seja retornada nos detalhes públicos do item, esta implementação didática não deve ser considerada apropriada para armazenar dados reais sensíveis.
- A busca textual usa consultas `LIKE`, em vez de um mecanismo dedicado de busca.

## Escopo

A decisão aplica-se à versão local para fins acadêmicos e de apresentação. Se o sistema passar a ser utilizado por uma instituição, a escolha do banco deve ser reavaliada junto com requisitos de backup, disponibilidade, controle de acesso e operação compartilhada.
