# ADR-004 — Execução local por um único comando

- **Status:** Aceita para a versão local simplificada do MVP
- **Data:** 2026-10-22

## Contexto

A aplicação será apresentada em computadores que podem não possuir o ambiente de desenvolvimento do projeto original. É importante reduzir as etapas manuais e evitar depender de internet, hospedagem externa ou serviços em nuvem durante a demonstração.

## Decisão

Executar frontend, API e acesso ao banco no mesmo processo local Python. O servidor escuta apenas em `127.0.0.1:8000`, serve o arquivo `index.html`, atende as rotas `/api/...` e armazena os uploads na pasta `uploads/`. No Windows, o script `executar.bat` inicia a aplicação e `app.py` abre o navegador no endereço local.

O único requisito externo é uma instalação funcional do Python 3.10 ou superior. Não se exige conexão com a internet durante o uso da aplicação, depois que o Python já estiver instalado.

## Alternativas consideradas

- **Frontend, backend e banco em serviços separados:** permite implantação independente, mas exige configuração de vários serviços.
- **Aplicação apenas estática:** seria muito simples, mas não demonstraria operações reais de backend nem persistência relacional.
- **Servidor local único com SQLite:** escolhido porque permite mostrar a interface, a API e os dados persistentes na mesma máquina com configuração mínima.

## Consequências

### Positivas

- A apresentação começa com um duplo clique em `executar.bat`.
- O navegador abre automaticamente em `http://127.0.0.1:8000`.
- A API e a persistência funcionam sem acessar serviços externos.
- O banco de dados permanece na pasta `data/` entre execuções.

### Negativas e limites conhecidos

- O computador da apresentação precisa ter Python instalado corretamente.
- A aplicação só é acessível localmente; outros computadores não conseguem acessar `127.0.0.1` do apresentador.
- Se a porta 8000 já estiver ocupada, é necessário encerrar o outro processo ou alterar a configuração de porta no código.
- Encerrar o servidor encerra as sessões em memória, embora os registros no SQLite permaneçam.

## Escopo

Esta decisão prioriza a apresentação acadêmica local. Ela não descreve uma implantação web pública ou multiusuário.
